# KABi Employee of the Month — حزمة النشر على GitHub Pages

نظام التصويت الشهري: صفحة واحدة (`index.html`) بدون داتابيس — الإكسل هو المرجع، وكل شهر ورقة باسمه (Sep 2026…).

## محتويات الحزمة
| الملف | الوظيفة |
|---|---|
| `index.html` | صفحة التصويت + كونسول IC (نسخة الإنتاج، الإرسال الحقيقي مفعّل) |
| `receiver/google-apps-script.gs` | المستقبِل المجاني: يكتب كل صوت في Google Sheet بورقة لكل شهر |
| `receiver/power-automate-flow.md` | المستقبِل المايكروسوفتي: يكتب في KABi-EOM-Master.xlsx على OneDrive |

## الخطوة 1 — جهّز المستقبِل (اختر واحدًا)

### الخيار A — Google Apps Script (مجاني، ~15 دقيقة)
1. افتح `sheets.new` → **Extensions → Apps Script** → احذف الموجود والصق محتوى `google-apps-script.gs` → Save.
2. عدّل بأعلى الكود: `SECRET = "KABI-IC-2026"` (نفس رمز IC الذي ستضعه في الصفحة).
3. **Deploy → New deployment → Web app**: `Execute as: Me` و `Who has access: Anyone` → **انسخ رابط Web app**.
4. ارجع للجدول: ستجد ورقة **Roster** أُنشئت تلقائيًا عند أول طلب — عبّئها: `ID | Name | Email | JobTitle` (البريد @kabi.ai فقط). هذه هي القائمة التي يراها المصوّتون، وكونسول IC يضيف/يحذف فيها مباشرة.

### الخيار B — Power Automate (داخل مايكروسوفت، يتطلب Premium لحساب IC)
اتبع `receiver/power-automate-flow.md` ثم انسخ **HTTP URL** الخاص بالمشغّل.

## الخطوة 2 — اضبط `index.html` (3 قيم فقط)
افتح الملف وعدّل أعلى قسم الإعدادات:
```js
let SUBMIT_ENDPOINT = "https://script.google.com/macros/s/....../exec";  // رابط المستقبِل من الخطوة 1
const IC_MAILBOX  = "ic@kabi.ai";        // بريد IC (لدخول الكونسول)
```
> **رمز IC لا يوجد في الصفحة إطلاقًا** — يكتبه IC عند بوابة الدخول ويتحقق منه المستقبِل (`SECRET` في السكربت). غيّر `SECRET` قبل الإطلاق ولا تشاركه خارج IC.
> قائمة الموظفين داخل الملف **عيّنة تجريبية فقط** — عند وجود المستقبِل تُحمَّل القائمة الحقيقية منه تلقائيًا، وكذلك الشهر الحالي وحالة الفتح/الإغلاق.

## الخطوة 3 — النشر على GitHub Pages
1. أنشئ Repository جديدًا (ملاحظة: Pages من ريبو **خاص** يتطلب خطة GitHub مدفوعة؛ الريبو العام يعمل مجانًا — لا مشكلة لأن القائمة الحقيقية لا تُخزَّن في الكود).
2. ارفع `index.html` (وملف README إن رغبت) إلى جذر الريبو.
3. **Settings → Pages** → Source: `Deploy from a branch` → Branch: `main` / `(root)` → Save.
4. بعد دقيقة يظهر الرابط: `https://<username>.github.io/<repo>/` — هذا هو رابط التصويت الذي تضعه IC في دعوة البريد.

## الخطوة 4 — اختبار قبل أول دورة (5 دقائق)
1. افتح الرابط → صوّت باسم موظف من الـ Roster → يجب أن يظهر الصف فورًا في ورقة الشهر بالجدول.
2. أعد التصويت بنفس البريد → «You've already submitted your vote for this month».
3. جرّب بريدًا خارج @kabi.ai أو غير موجود بالقائمة → رفض.
4. ادخل كونسول IC (Internal Communication + بريد IC + الرمز) → **Refresh live data** → تظهر الأصوات والنِسَب.
5. من الكونسول: **Close voting** → افتح الرابط من جهاز آخر → «Voting has closed» → أعد الفتح.

## الروتين الشهري (كله من الكونسول — بدون لمس GitHub)
افتح دورة الشهر (Start new cycle) → أرسل الدعوة (Copy designed email + Open empty draft) → تابع النِسَب وذكّر غير المصوّتين → عند الإغلاق أعلن الأبطال → **خذ الإكسل**: من Google Sheet: `File → Download → Microsoft Excel` (كل شهر ورقته)، أو زر `Excel — this month` من الكونسول للنسخة المصمّمة فورًا.

## ملاحظات أمان
- الرابط عام؛ الحماية الفعلية **في المستقبِل**: نطاق @kabi.ai، عضوية الـ Roster، منع التكرار والتصويت الذاتي، وحالة الفتح/الإغلاق — كلها تُفحص سيرفريًا ولا يمكن تجاوزها من المتصفح.
- لا تشارك رابط جدول الأصوات أو ملف الماستر مع أحد خارج IC، وغيّر `IC_PASSCODE/SECRET` قبل الإطلاق.
- ترقية الهوية لاحقًا (تسجيل دخول مايكروسوفت الحقيقي عبر Graph) لا تغيّر شيئًا من هذه البنية — نقطة الاستبدال واحدة في الكود.
